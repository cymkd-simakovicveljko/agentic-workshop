# Section 7 — historical owner-search examples

## Understand

The retained files in this directory describe the **pre-simplification project
directory's owner-search proposal**. Their shared brief, FSAD-style session and
OpenSpec tree belong to that earlier app. They are historical authored examples,
not current todo-app requirements, implemented behavior or evidence of an active
framework integration. Do not use their paths or old structural-check instructions
to start the current exercise.

## Watch or try

Use the [active comparison lab](../section-07-flavor-lab.md), which contains the
worked todo-app examples **inline**:

- [Plain OMP brief](../section-07-flavor-lab.md#route-a-plain-omp-brief): current
  behavior, proposed filter, scope, plan and unperformed checks in one small brief.
- [FSAD-style discussion](../section-07-flavor-lab.md#route-b-fsad-style-discussion-and-decision-record):
  product, UX and engineering distinguish hiding from deletion, resolve the view
  decision and record its rationale.
- [OpenSpec-shaped change record](../section-07-flavor-lab.md#route-c-openspec-shaped-change-record):
  current requirements, proposed visibility delta, design and unchecked tasks.

All three receive the same unfinished-filter acceptance examples A1–A6. No route
requires framework installation or copying these historical files into the app.
The active OpenSpec-shaped example is illustrative, not a CLI-validated artifact
pack. The FSAD dialogue is authored, not a captured stakeholder meeting.

## Use at work

Choose one maintained proposal if the comparison moves to implementation. Preserve
useful historical reasoning without treating old contracts as active authority.
A discussion note can link to the current requirement instead of repeating it in
another specification. Current code, proposed behavior and observed verification
must remain distinguishable whichever format you choose.
