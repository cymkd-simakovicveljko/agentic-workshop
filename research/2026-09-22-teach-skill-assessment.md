## Recommendation

**Do not make this a required OMP-course skill or import its implementation.** Treat it as an optional, source-read case study in proposed section 5, **Steering agents**, next to the current skills comparison. It demonstrates a useful contrast: a skill can own a durable, task-specific workspace, not merely improve an in-session answer. The current course should keep its focused evidence-review procedure and its distinction between discovery, loading and useful judgment.

The repository calls the skill **`teach`**, not `teach-me`. Its frontmatter names `teach` and disables implicit model invocation; its OpenAI adapter likewise requires explicit invocation. The pinned productivity directory contains `teach` but no `teach-me` entry. That makes it a plausible referent, not proof that it is the user's intended “teach me” skill. Confirm the name/source before connecting it to a product or prior evaluation. ## What the pinned skill actually instructs

**Source snapshot.** These findings inspect `mattpocock/skills` at commit [`c55ee46073ed923f86ce59a5eb3b6d895095d1b7`](https://github.com/mattpocock/skills/tree/c55ee46073ed923f86ce59a5eb3b6d895095d1b7), whose `main` tip was dated 18 September 2026. This is source review, not an installation or runtime test.

- **Grounding:** Before teaching, it tells the agent to build `RESOURCES.md` from high-trust resources rather than parametric knowledge. The format separates knowledge sources, wisdom/community sources and explicit gaps; every entry needs an annotation. A mission file records the practical goal, observable success, constraints and scope, and the skill says that mission should steer each lesson. [Skill](https://github.com/mattpocock/skills/blob/c55ee46073ed923f86ce59a5eb3b6d895095d1b7/skills/productivity/teach/SKILL.md) · [resource format](https://github.com/mattpocock/skills/blob/c55ee46073ed923f86ce59a5eb3b6d895095d1b7/skills/productivity/teach/RESOURCES-FORMAT.md) · [mission format](https://github.com/mattpocock/skills/blob/c55ee46073ed923f86ce59a5eb3b6d895095d1b7/skills/productivity/teach/MISSION-FORMAT.md)
- **Interaction:** The primary output is one short, self-contained HTML lesson for one tightly scoped, mission-linked win. It asks for citations, a recommended primary source and follow-up questions. It directs skill practice toward quizzes or browser tasks with immediate feedback, retrieval practice and, as design principles, spacing and interleaving. These are instructions to a model, not evidence that a given lesson supplies valid feedback or long-term retention.
- **Assessment:** It has no explicit initial knowledge test. Instead, it infers the next lesson from the mission and `learning-records`; a record is written only for demonstrated understanding, disclosed prior knowledge, corrected misconceptions or a changed mission. The open request for a knowledge-assessment feature supports the narrower claim that this is not currently specified behaviour. [learning-record format](https://github.com/mattpocock/skills/blob/c55ee46073ed923f86ce59a5eb3b6d895095d1b7/skills/productivity/teach/LEARNING-RECORD-FORMAT.md) · [issue #725](https://github.com/mattpocock/skills/issues/725)
- **Persistence and outputs:** The skill defines a stateful workspace: `MISSION.md`, `RESOURCES.md`, `NOTES.md`, numbered HTML lessons and references, numbered Markdown learning records, plus reusable browser components in `assets/`. A new session is meant to continue by reading those artifacts, not chat history. This is a stronger persistence model than a single prompt, but it also writes a small course into the working directory.
- **Tools and dependencies:** No executable tool, script, provider API, package or browser dependency is declared in the skill directory's metadata; the adapter only sets a display name and explicit invocation policy. The instructions do require filesystem reads/writes and optionally ask the agent to open a generated lesson through a CLI command. Interactive HTML assumes a browser is available to the learner. Neither the source nor this review establishes how an OMP host would route, authorize or execute those actions. [OpenAI adapter](https://github.com/mattpocock/skills/blob/c55ee46073ed923f86ce59a5eb3b6d895095d1b7/skills/productivity/teach/agents/openai.yaml)

## Limits that matter here

1. The skill uses `./` both for its own format files and for learner-workspace artifacts. An open report says this has placed generated lessons in an installed skill directory rather than the intended working directory. Do not use the course repository as its workspace; any pilot needs an explicit, isolated output directory and an inspection of the first output location. [issue #377](https://github.com/mattpocock/skills/issues/377)
2. The documentation says the skill is explicitly invoked and intended for a multi-session learning project, not a passing explanation. That conflicts with using it as invisible machinery under the core course or as evidence that OMP selected a skill naturally. [teach documentation](https://github.com/mattpocock/skills/blob/c55ee46073ed923f86ce59a5eb3b6d895095d1b7/docs/productivity/teach.md)
3. The source asks the model to produce citations and feedback loops, but neither property proves the source is correct, that a quiz is fair, or that learning occurred. The documentation itself advises checking primary sources. For OMP material, runtime claims still require host evidence, exactly as the current course says.

4. `GLOSSARY-FORMAT.md` is present in the skill directory, but `SKILL.md` does not link it. The upstream documentation calls this out; do not make a course glossary or its vocabulary rules a hidden prerequisite. [glossary format](https://github.com/mattpocock/skills/blob/c55ee46073ed923f86ce59a5eb3b6d895095d1b7/skills/productivity/teach/GLOSSARY-FORMAT.md)

## Fit with the existing course

The then-section 3 taught an engineering loop from exploration through verification and separated accepted outcome, implementation and observed evidence. `teach` can help someone learn those ideas over time, but it must not replace browser/test evidence or code-state review. Its HTML quiz is pedagogical output, not OMP execution evidence. [Maintained workflow, now section 4](../sections/04-the-everyday-workflow.md#six-decisions-not-six-compulsory-prompts)

The closer fit is section 5. Its comparison asks learners first to review ordinarily and with a small pasted procedure, then judge exact evidence, unsupported claims and scope discipline. It separates a pasted procedure from registered-skill discovery and loading. `teach` reinforces the broader point that a skill is instructions and artifacts, not an enforcement boundary, but its large workspace is a poor replacement for that compact review procedure. [Maintained comparison](../sections/05-steering-agents.md#compare-a-procedure-with-ordinary-review) · [lab](../demo/section-05-skill-lab.md#understand)

**Placement:** add a short optional case-study callout in proposed section 5, **Steering agents** (currently `sections/05-skills.md`), after the existing comparison and before native OMP invocation. It should point forward to proposed section 7, **Shipping across sessions**, for the durable-artifact idea. Do not add it to the ordinary workflow's core path: a separate course-generation workspace is a different job from safely changing a repository.

## Bounded comparison exercise

Run this only as a separately approved pilot, in two fresh isolated teaching workspaces, never in the course or learner project repository. Pin the same `teach` revision and use the same model/settings. Supply both conditions with the same learning goal and short OMP skill-lifecycle packet: a pinned OMP skills-guide excerpt plus the current section 5 explanation of discovery, body loading and useful judgment. Allow both conditions to retain learning notes and resume in a fresh session. Record inputs, output paths and actual tool activity. This compares plain teaching with the skill, not code review with teaching.

| Condition | Learner work | Observable success |
| --- | --- | --- |
| Plain teaching baseline | Read the current course explanation and ask the agent to teach the shared learning goal without the `teach` skill. Answer the close-negative request: “Does explicit `/skill:name` invocation prove natural selection?” Retain a short learning note and resume in a fresh session. | Correctly distinguishes discovery, loading and judgment; says explicit invocation does **not** prove natural selection; preserves the distinction in the fresh session; does not claim runtime observations without a record. |
| `teach` pilot | Explicitly invoke the pinned `teach` skill in the isolated workspace for the same packet and close-negative request, then begin a second fresh session from that workspace. | Produces a cited lesson and one compressed reference; its files appear in the declared workspace; the second session uses the prior artifacts; the learner reaches the same correct close-negative answer without a false natural-selection claim. |

Score the learner's answers against the same four facts: (1) metadata discovery is not body loading, (2) loading is not useful judgment, (3) explicit invocation is not natural selection, and (4) skill instructions do not enforce host permissions. Require source locations for all four. Keep the pilot only if the skill adds a useful learning or continuation benefit without false runtime claims or workspace pollution. Record prior familiarity and order effects; if one learner tries both conditions, the second attempt benefits from the first. Generated output quality alone is not evidence of learning, and one short trial does not establish retention.

## Required adaptation; do not import

Adapt only the durable-learning pattern: explicit mission, a short initial knowledge check, curated OMP primary sources, compact learning records with evidence, and an explicit workspace root. Curate the OMP source list in advance; do not let a course exercise silently substitute a model-selected source. Add an actual pre-assessment because the upstream skill lacks one, and preserve the course's evidence rules for every claim about OMP behaviour.

Do **not** copy the upstream skill wholesale, install it as a course prerequisite, create its HTML/component tree inside this repository, or treat its quizzes, citations, community referrals or stated learning principles as demonstrated teaching effectiveness.
