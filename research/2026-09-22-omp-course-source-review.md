# OMP course source review — 2026-09-22

## Scope and source boundary

This reviews the high-risk OMP claims in `sections/01*`, `02*`, `04*`, `05*`, `06*`, `08*`, and `demo/section-01-setup.md`. It is a source review, not a provider, browser, skill, or classroom-runtime test.

The observed local CLI version is `omp/18.2.9`. Local `omp --help` also advertised `setup`, `--continue`, `--resume`, `--approval-mode always-ask|write|yolo`, `--thinking off|minimal|low|medium|high|xhigh|max|auto`, `stats`, `usage`, and `acp`. That is local command-surface evidence only: no provider, usage, stats, browser, skill, or agent action was executed. The matching upstream tag is [`v18.2.9`](https://github.com/can1357/oh-my-pi/tree/v18.2.9), commit [`8cd6f8c619e89e935b6c6c5c91f6a4d20f6d7a75`](https://github.com/can1357/oh-my-pi/commit/8cd6f8c619e89e935b6c6c5c91f6a4d20f6d7a75); its package manifest declares `18.2.9` ([source](https://github.com/can1357/oh-my-pi/blob/8cd6f8c619e89e935b6c6c5c91f6a4d20f6d7a75/packages/coding-agent/package.json)). The upstream `main` observed during this review is [`b84f082e5b40494a253f6c1fecc5cf8bf17011d2`](https://github.com/can1357/oh-my-pi/commit/b84f082e5b40494a253f6c1fecc5cf8bf17011d2), not the tag. Its manifest still says `18.2.9`, but that does **not** prove the local binary was built from that commit or has its settings, extensions, credentials, or tool surface.

**Recommendation:** replace lesson references framed as “current official documentation” with `OMP 18.2.9 documentation`, linked to the tag. Keep `main` links only when explicitly labelled upstream/latest, never as evidence of the classroom runtime.

| Model/provider distinction and model/effort/usage surfaces — 01, 02 and setup demo | **Partly supported** | Provider/model identity, provider-scoped credentials, `--model`, `--smol`, `--slow`, `--plan`, and thinking levels are documented. | Context-file discovery, precedence and `/extensions` — 02 and 04 | **Supported** | Native `.omp/AGENTS.md` comes from the nearest non-empty `.omp/` directory on the cwd-to-repository-root walk; a missing file there does not fall back to a farther native directory. Standalone `AGENTS.md` and `CLAUDE.md` can be discovered up ancestor paths, including enclosing workspace directories for repositories under home. One user context file survives; one project file survives per directory depth; higher-priority providers shadow at the same depth; farther ancestors are injected before nearer files. Deeper, not-auto-loaded `AGENTS.md` files are pointers to read before editing. `/extensions` exposes discovered files and state. |
| Skills, `SKILL.md`, `skill://` and discovery scope — 05 | **Supported, with a missing conditional** | Skills are file-backed packs. With `read` available, visible skill metadata is exposed in the system prompt and content is available through `skill://<name>`. `/skill:<name>` commands require `skills.enableSkillCommands`, a condition the current optional lesson already states. Add the `read`-availability and hidden-skill conditions to the general metadata explanation. Discovery is one directory level below each skills root. Provider duplicates resolve by precedence; custom-directory skills can override default provider skills. |
| `/resume`, `/new`, `/fresh`, `/restart` — 06 | **Supported** | `/resume` and CLI `--resume` choose saved sessions; their no-argument selectors start in current-folder scope, with a user-triggered all-projects view. `/new` creates an empty conversation and new session identity. `/fresh` keeps the local conversation/session file but resets provider-facing stream state; it is rejected while streaming. `/restart` relaunches OMP with original launch flags and resumes the current session. A cross-project resume can switch the process cwd. None reconciles the working tree, browser storage, subprocesses, or remote effects. |
| Compaction and automatic compaction — 02, 04, 06 and 08 | **Partly supported; practical control is omitted** | The generic course claim that summaries can lose vital detail is sound. Compaction preserves a summary plus selected recent entries for model context; it is not a current-state inventory. The source documents mechanisms, not that a given local session will compact: effective settings, model compatibility, thresholds and the actual context determine that. |
| Subagent history, isolation, headless approval and control — 06 and 08 | **Supported** | `task` children do not inherit parent conversation history. They receive the working tree, discovered skills/context files, shared `local://` data and, when applicable, an approved-plan reference; the assignment must carry the task-specific context. Non-isolated children use the parent cwd. Isolation is conditional on `task.isolation.enabled`, disabled in plan mode, and requires a Git repository; isolated children are not revivable after cleanup. Child sessions force `tools.approvalMode: yolo` because they are headless; user `deny` remains blocking and `prompt` rejects because it cannot be answered. Agent Hub supports inspect, steer, revive and `x` kill/release; returning from a child with `Esc` does not interrupt it. |

### Concrete discrepancies and gaps

No material command claim in the reviewed passages is contradicted by the tagged 18.2.9 sources. The issues are versioning and omitted conditions:

1. **`main` is used as though it were the local runtime.** Every course link reviewed points at `main`, while the local evidence is version plus help text, not `main` provenance. This can silently teach controls added, removed or changed after the installed build.
2. **“Current documentation” overstates what is known.** It supports documented behavior, not a learner’s effective configuration. Approval overrides, disabled providers/extensions, remapped keys, an unavailable `read` tool, and missing credentials can change the surface.
3. **Skill exposure is conditional.** Keep the existing `skills.enableSkillCommands` qualification. Add that the discovered list is omitted without `read`, and hidden skills are excluded from that list without becoming unavailable to explicit invocation. Provider duplicates are first-wins by precedence, but custom-directory skills can override default-path provider skills. Inspect the resolved source, not just the name.
4. **Task effort is feature-gated.** Do not prescribe `effort: lo|med|hi` as a standard learner action. The field is absent unless `task.enableEffort` is enabled.
5. **Session controls have distinct interactive and launch surfaces.** The reviewed lessons use `/new`, `/fresh`, and `/restart` correctly as slash commands. Do not translate them into invented `--new`, `--fresh`, or `--restart` flags: tagged launch controls are `--continue` and `--resume`; `/new` and `/restart` are TUI controls.
6. **Compaction is not recovery.** `/compact` or automatic compaction reduces context pressure. It does not verify disk/process/browser state, preserve every requirement, or establish a safe handoff.
7. **No live claim is justified.** The sources do not establish successful provider login, chosen model availability, browser control, skill invocation, isolation backend selection, or task execution in this course environment.

## Practical teaching candidates for the proposed revision

These are documented controls worth teaching as short, evidence-first exercises. They are candidates, not a decision to change the curriculum.

1. **Getting started / How agents work — inspect the effective surface.** Teach `omp --help`, `/hotkeys`, `/model`, and, only if authorized and needed, `/login`. Learners record the actual model/provider and bindings, then distinguish that observation from product documentation. The prepared route remains valid without authentication; the live route requires configured, authorized provider access.
2. **Working with OMP — approval is a policy resolution, not a sandbox.** Keep `--approval-mode always-ask` as the course default and show the three tiers. Pair it with the documented counterexample: a `bash` rule alone does not constrain `eval`. The lesson should stop at policy inspection; environment containment needs an independent control.
3. **Everyday workflow / Steering agents — model, thinking and usage inspection.** Teach model selection and thinking as session controls, not capability guarantees. `omp stats` and `omp usage` can be optional inspect-only actions for authorized accounts; neither should promise a particular statistic or usage result, and neither should expose credentials. Reserve per-task effort for an advanced, configuration-aware example.
4. **Reliable execution / Shipping across sessions — choose the right reset.** A decision table for `/fresh`, `/clear`, `/new`, `/resume`, and `/restart` would be more useful than a command list. The exercise should require a filesystem/process/diff inventory before and after, because session controls do not reconcile external state.
5. **Context and skills — trace provenance.** Use `/extensions` to inspect which context files were discovered and explain depth/priority shadowing. For skills, inspect metadata and the resolved source separately from output quality. A source walkthrough supports a prepared route; it does not close the proposed hands-on packaging/loading exercise or prove invocation on the teaching runtime.
6. **Advanced harness / enterprise — delegate with explicit boundaries.** Show that a child gets task text, workspace/context discovery and selected inherited surfaces, not the parent transcript. Require a complete assignment, name ownership, inspect effective child tool policy, and treat isolation as opt-in file-collision control rather than security isolation. Agent Hub is a suitable observation surface, not proof that child side effects were reversed.
7. **Long sessions — preserve external state before compaction.** Teach `/compact` as an optional, version-pinned control alongside a durable handoff containing revision, dirty work, test evidence, active operations and the next discriminating action. Automatic compaction should be described as possible maintenance, never assumed to have run.
